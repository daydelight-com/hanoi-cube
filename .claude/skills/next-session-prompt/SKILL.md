# next-session-prompt: 次セッション開始プロンプトの生成

指定されたセクション(例: `S2`)の開始プロンプトを、下のテンプレートに従って生成する。
出力はプロンプト本文のみ(前置き・解説を付けない)。オーケストレータがそのまま
新セッションの初回メッセージとして使える形にする。

## 手順

1. `docs/development_plan.md` §4 のセクション表から該当行(成果物・DoD)を読む。
2. `docs/handoff/` の直前セッションの handoff を開き、「次セッションへの注意」と
   要判断事項の有無を確認する(全文を転記しない。参照指示を書くだけ)。
3. 直前 handoff に「次セッションへの注意」として書かれた申し送りのうち、
   該当セクションに関係するものだけをプロンプトの「申し送り」に要約して入れる。
4. テンプレートを埋めて出力する。

## テンプレート

```
S{n} を担当してください: {セクション名}

## 成果物

{development_plan.md §4 の成果物欄を転記}

## 完了条件(DoD)

{development_plan.md §4 のDoD欄を転記}

## 開始時に読むもの(この順で。リポジトリ全体を読まない)

1. docs/handoff/S{n-1}.md(直前セッションの handoff)
2. {関係する契約ファイルを列挙。例: docs/contracts/ws-messages.md, docs/contracts/screens.md}
3. docs/specification.md の該当節: {直前 handoff・契約から特定した§番号}

## 申し送り

{直前 handoff の「次セッションへの注意」から該当分のみ要約。無ければ「特になし」}

## 無人実行時の注意

- 実機・目視が必要で無人では検証できないDoD項目は、代替手段で可能な範囲まで検証し、
  残りを handoff に「未検証・要人間確認」として明記して進める。
- 契約・仕様の不明点は CLAUDE.md 規則3の通り「要判断」として handoff に記録し、
  妥当なデフォルトで進める。ユーザーへの質問で作業を止めない。

完了したら /finish を実行してセッションを終えてください。
```

## 禁止事項(生成時に混入させない)

- **締切・所要時間・速度に関する記述を入れない**。「8/7までに」「半日以内で」
  「急いで」等は品質を落とす方向に働くだけで、締切情報は CLAUDE.md が既に持っている。
- 直前 handoff や仕様書の長文転記をしない(読む対象の指定で足りる)。
- テンプレートにない指示(実装方針の先回り指定など)を勝手に足さない。
  実装判断は次セッションが契約と仕様から行う。
