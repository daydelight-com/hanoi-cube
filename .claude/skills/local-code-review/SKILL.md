# local-code-review: 変更差分のコードレビュー

ビルトイン `/code-review` はモデルから起動できないため、その代替としてエージェント自身が行う精査手順。
指摘の列挙までがこのスキルの範囲。**修正は行わない**(super-review 側の役割)。

## 手順

1. **範囲確定**: `git status` / `git diff`(未コミット)と `git log origin/main..HEAD --oneline` +
   `git diff origin/main..HEAD`(未プッシュ)で対象差分を出す。
2. **観点別レビュー**(差分が大きい場合は Explore / general-purpose サブエージェントを観点ごとに並行起動する):
   - **正しさ**: ロジックのバグ、境界条件(空盤面・0点・満杯・タイムアップ境界)、例外処理、
     off-by-one、非同期・並行の競合
   - **契約整合**: `docs/contracts/` と実装(Python / TS 写し)の一致。契約内の例示・数値は検算する
   - **仕様整合**: handoff に記載された仕様書該当節・ルールブックとの矛盾
   - **テスト**: 変更に対するテストが同セッションで書かれているか、境界と異常系を踏んでいるか
   - **設計**: 密結合(判定ロジックにWS、描画に状態遷移を混ぜる等。計画§6は密結合を品質不合格とする)、
     重複、不要な複雑さ
3. **検証**: 各指摘は該当コードを実際に読み直して再検証し、誤検知・意図的な設計を落とす。
4. **報告**: 検証済みの指摘を「ファイル:行 / 重要度(High/Med/Low)/ 内容 / 根拠」で列挙する。
   指摘ゼロならゼロと明記する。
