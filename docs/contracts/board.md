# 契約: 盤面表現(board)

盤面(論理盤面)の正準形。全モジュール(ゲームコア・CV・サーバー・フロント・記録画面)はこの表現を共有する。
ルールの正: [../game/hanoi_arrange_rules.md](../game/hanoi_arrange_rules.md)

## 1. サイズ文字

| 文字 | サイズ | 一辺 |
|---|---|---|
| `L` | 大 | 75mm |
| `M` | 中 | 50mm |
| `S` | 小 | 30mm |

## 2. 塔文字列(tower string)

- 1つの塔 = **下から上の順**にサイズ文字を並べた文字列。空塔は空文字列 `""`。
- 合法な塔状態は次の8通りのみ(ルールブック§3)。**この並び順を塔状態インデックス 0〜7 とする**。

| index | 文字列 | 意味(下から) |
|---:|---|---|
| 0 | `""` | 空 |
| 1 | `S` | 小 |
| 2 | `M` | 中 |
| 3 | `L` | 大 |
| 4 | `MS` | 中, 小 |
| 5 | `LS` | 大, 小 |
| 6 | `LM` | 大, 中 |
| 7 | `LMS` | 大, 中, 小 |

## 3. 盤面文字列(board string)

- 3塔(A/B/C の順)の塔文字列を `/` で連結する。**空塔は空文字列**(プレースホルダなし)。
  - 例: `LMS//L` = A:[大,中,小] B:空 C:[大](仕様書§7.1 と同形式。SQLite / Firestore にもこの形式で保存する)
  - 注: development_plan.md §3 の例 `LMS/-/L` とは異なる。`-` は使わない(要判断 → handoff/S0.md 参照)。
- 正規表現(合法盤面): `^(|S|M|L|MS|LS|LM|LMS)/(|S|M|L|MS|LS|LM|LMS)/(|S|M|L|MS|LS|LM|LMS)$`
- 盤面は 8×8×8 = **512通り**。物理の箱は各サイズ3個なので全512通りが実現可能。
- 盤面文字列は**塔上の箱のみ**を表す。待機エリアの箱は含まない。得点計算の「円盤の総数」= 盤面文字列中のサイズ文字数。

### 不正盤面(CV検出用)

CVは配置ルール違反(小の上に大など)を検出する。違反時の生スタックは塔状態8通りに収まらないため、
`SL` のように**下から上の順の任意のサイズ文字列**で表現する(cv-interface.md の `towers` フィールド)。
合法盤面のみが上表の8状態に一致する。判定エンジンに渡してよいのは合法盤面のみ。

## 4. 盤面インデックス(0〜511)

```
index(board) = idxA * 64 + idxB * 8 + idxC   (idxX = 塔状態インデックス 0〜7)
```

事前計算テーブル(game-core-api.md)の配列添字はこの値を使う。

## 5. 鏡像と正準化

- **鏡像(mirror)**: A塔とC塔を入れ替えた盤面。`mirror("LMS//L") = "L//LMS"`
- **正準キー(canonical_key)**: 盤面文字列とその鏡像の盤面文字列のうち、**辞書順(バイト順)で小さい方**。
  - 例: `canonical_key("LMS//L") = min("LMS//L", "L//LMS") = "L//LMS"`
  - 左右対称な盤面は自分自身が正準キー。
- **重複判定**(ルールブック§6「鏡像は同じ配置とみなす」)は canonical_key の一致で行う。
- ハッシュ値は別途定義しない。canonical_key(文字列)をそのまま辞書キー・照合キーに使う。

## 6. 実装の対応

- Python: `server/app/core/board.py`(parse / format / validate / mirror / canonical_key / index)
