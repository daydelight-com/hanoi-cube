# S7 引き継ぎ: CV PoC

## 完了したこと

無人セッションのため実カメラ・印刷タグの検証は不可。**合成画像による代替検証**で
「黒枠16mmの妥当性判定」と「S8実装用の閾値決定」まで行い、実機検証はツールを整備して
手順化した(残項目は下記「未検証・要人間確認」)。

- `docs/cv_poc.md` — **PoC結果報告書(S8はこれを読むこと)**。結論:
  - **静止検出は黒枠16mmで妥当**(1080p・画角幅75cm・視線角0〜60°で検出率100%、
    余裕1.4〜2倍)。対処順(2枚目/寄せる/4K)の発動は**不要**
  - **移動追従の支配要因は露出時間**(モーションブラー)。ブラーが「ブラー方向に投影された
    タグ辺」の約20%を超えると検出崩壊。横移動(塔間)は露出1/125sで約390mm/sまで追従可、
    縦移動(持ち上げ)はその約半分。1/60s(暗い会場)では移動中ほぼ全ロスト。
    ただしロスト保持(仕様§4.2の2秒)+静止後0.3秒確定で**ゲーム進行は照明が暗くても成立**
    (影響は移動中の3D表示の滑らかさのみ)
  - 対処順「寄せる/4K」は**ブラーには中立で効かない**(タグpxとブラーpxが同率増)。
    ブラー対策は会場照明を明るくして自動露出を短くすること(連係カメラは露出制御不可)
  - **S8の検出器初期値**: `Detector(families="tag36h11", nthreads=4, quad_decimate=2.0,
    quad_sigma=0.0, refine_edges=True, decode_sharpening=0.25)`、
    受理条件 `hamming<=1 かつ decision_margin>=15 かつ tag_idがtag_master.jsonに存在`
  - スループット(検出のみ・開発Mac): 1080p・22タグで decimate=2.0/4thr が 14ms/frame。
    ただし取得・変換・盤面構成・IPCは未計測。**30fps予算の最終判定はS8のパイプライン全体で**
- `scripts/cv_poc_synth.py` — 検出限界スイープ(黒枠px×視線角×ブラー×露出、432計測点×24試行、
  hamming内訳・別ID誤検出数・gain別検出率を保存)+物理シナリオの直接計測
  (角度45/60°×ブラー長軸/短軸の最悪値で判定)。生データ `output/cv_poc_synth_results.json`
  (gitignore下、再実行で再生成可)
- `scripts/cv_poc_perf.py` — 1080p・22タグ(9箱×2面+マット4)のスループット計測
- `scripts/cv_poc.py` — **実機PoC用の計測CLI**。検出率・黒枠px・px/mm(マット四隅から自動算出)・
  margin・**箱単位の追従ギャップ**(6面のいずれか見えていれば追従扱い。先頭・末尾の
  未検出区間も含む)・判定目安を出力。docstringに実機手順。`--synthetic` で自己検証可(検証済み)

## 要判断(選んだデフォルトと理由)

1. **scripts/ は make check の対象外**(前例: generate_tag_sheet.py)。テストの代替として
   各スクリプトに自己検証モード(`--quick` / `--synthetic`)を持たせ、server の ruff 設定での
   lint はクリーンにした。本番コード(S8の server/app/cv/)は通常どおりテスト必須
2. **DoD「中箱を速く動かして追従が破綻しない」の解釈**: 毎フレーム検出が続くことではなく、
   「ロスト保持(2秒)内で3D表示が飛ばない+置いた後0.3秒で盤面確定」が成立すること、とした。
   移動中の毎フレーム検出は露出1/60sでは物理的に不可能なため(docs/cv_poc.md §3)
3. **受理条件に hamming≤1 を採用**: 劣化境界の検出失敗は全件「正IDのビット誤り訂正」で、
   別IDへの誤検出は1万レンダリング超でゼロだったため(保存データの other_id / h12_only 列で
   再現可能)。さらに ID∈マスタで防御
4. **decision_margin 閾値は 15**(当初20としたが、視線角60°+ブラー時の有効検出の
   margin実測が17.2〜18.8のため、Codexレビュー指摘を受けて引き下げた)

## super-review の結果

- local-code-review: 軽微3件(未使用変数、型注釈の誤り、表示文言の不正確)を検出し修正
- security-review: 指摘ゼロ(入力=信頼済みCLI引数とリポジトリ内固定パスのみ、危険シンクなし)
- Codexレビュー: **12件(高5・中6・低1)、うち11件修正・全件正当**。結論を覆す指摘を含む:
  - 高: シナリオ判定が計測グリッドへの最近傍丸めで「500mm/s・1/125s=OK」と誤報告
    (実測0%)→ シナリオを実レンダリングによる直接計測に変更
  - 高: ブラーが常に長軸方向で、射影で縮む短軸方向を未評価(短軸は耐性が半分)
    → ブラー方向パラメータを追加し、シナリオは角度45/60°×方向h/vの最悪値で判定
  - 高: margin≥20 が境界の有効検出(min 17.2)を落とす → 15に引き下げ
  - 高: 追従ギャップがタグ単位+末尾ロスト無視で完全ロストでも0ms・OK表示
    → 箱単位集計+先頭末尾の未検出区間を含める+未検出箱は判定不能と表示
  - 中: 報告書の矛盾・過大結論(「タグ実寸拡大は無効」は誤り、30fps「予算内」は検出のみで
    過大、nthreads=8の記載が再現不能等)→ 報告書・perfスクリプトを修正
  - 中: tag_master.json 欠落時にIDフィルタが黙って無効化 → 起動時に明示警告
  - 低(修正): q終了時のフレーム数不整合。全指摘の詳細は本セッションのCodexログ参照
