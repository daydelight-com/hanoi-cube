# S22 引き継ぎ: ルール説明の図版化(子ども向け)+ タイトル「Cubeでハノイ」

ユーザー要望「ルール説明が分かりづらい。イラストを入れて小さい子でもすぐ理解できるように」に対応。
契約・サーバー側は無変更(ページ数 `page_count=5` は維持)。

## 完了したこと

### 1. ルールダイアログを「図が主役・文字は補助」に再構成

- `frontend/src/display/screens/ruleFigures.ts`(新規): 各ページの図版データ+レイアウト計算
  (純関数のみ。`RULE_FIGURES` は `RULE_PAGES` と同順・同数)。
  塔に積んだ箱を実物色(大=緑/中=橙/小=水色、`public/textures` の cube_l/m/s に合わせた)で
  描き、○×印・移動矢印・A/B/Cラベル・バッジ(得点式など)・コマ間の「→」「⇄(鏡線)」で
  文字なしでも意味が取れるようにした。
- `frontend/src/display/screens/RuleFigure.tsx`(新規): 上記データを外部画像なしの SVG で描画。
  バッジは `badgeLayout()` で文字数に応じて縮小しコマ幅(=viewBox)に収める(英語の得点式対策)。
- `RuleDialogScreen.tsx`: 枠を 72vw×72vh に拡大し、見出し(ページ番号付き)→図版(34vh)→短文の順に配置。
- `i18n/strings.ts` の `RULE_PAGES` を日英とも短文・ひらがな中心に書き直し。

各ページの図:
1. どんなゲーム?: 箱を積む → 「はんてい!」 → 「+18」
2. つみかた: ○(大→中→小)/ ×(小の上に大)/ ×(同じ大きさ)
3. うごかしかた: ○(大きい箱の上へ)/ ×(小さい箱の上へ)/ ×(下の箱を動かす)
4. クリアとは: 「さいしょ」⇄ 鏡線 ⇄「ひだりみぎ はんたい」
5. ポイント: 盤面 + 「6こ × 3て = 18」(ルールブック§5の最短3手の例と同じ配置)

## 契約からの逸脱・追加判断

- 契約変更なし。
- **採用判断**: ページ数は契約の5を維持し、各ページ「図版+3行程度」に収めた。図版データは
  言語非依存、キャプション/バッジだけ `Record<Lang,string>`(仕様§5.13「図版は日英2式」をデータで充足)。
- **採用判断**: 図版は外部画像(PNG)ではなく SVG コード生成。理由: 日英切替に追従しやすい、
  箱色・盤面変更時にデータだけ直せばよい、素材待ちにならない。ユーザー支給のイラストが
  来た場合は `RuleFigure` を `<img>` に差し替える設計にしている(データ型は流用可)。
- 「1つの塔に3個まで」は図では表現せず文言のみ(同サイズ禁止から自明で、4段の図は描けないため)。

## 次セッションへの注意

- ルール図版を直すときは `ruleFigures.ts` のデータ(`RULE_FIGURES`)とテストだけ触ればよい。
  ○×の整合はテストが機械的に検証する。
- `uvicorn --reload` が動いている状態で `make check`(server 側のキャッシュ書き込み)を走らせると
  サーバーが再起動して状態機械が idle に戻る。画面確認中は注意。
- `RULE_PAGES` の文言を変えるときはルールブック §5(クリア条件2)・§6(鏡像重複・最短手数)の
  3要素を落とさないこと(今回 Codex に指摘された点)。
