## 要判断(選んだデフォルトと理由)

1. **空塔の表記**: development_plan §3 は `LMS/-/L`、specification §7.1 は `LMS//L` で矛盾
   → **仕様書側 `LMS//L`(空塔=空文字列)を採用**(DB保存形式と一致、仕様書が契約内容の正のため)。`-` は不正形式として拒否
2. **「3言語ツールチェーン」の解釈**: server(Python)/ frontend(TS)/ cloud/record(TS)の**3ルート**を
   make check が実際に検査する構成とした
3. **Firestore の played_at**: Timestamp型ではなく **ISO8601文字列**(SQLiteと同表現・辞書順=時刻順で3番目の
   ソートキーにそのまま使えるため)。firestore.md に明記
4. **同点順位の第3キー**: 仕様§7.1「先着順」を `played_at ASC` で実装(複合インデックス定義済み)
5. **ゲーム画面の状態分割**: 仕様§5.1の「ゲーム画面」を `game_countdown` / `game_play` の2状態に分割
   (カウントダウン中の判定不可をガードでなく状態で表現)。ルールダイアログは `ctx.from` 持ちの独立状態
6. **リザルトのキーボード完了後の初期フォーカス**: 仕様に記載なし → `決定` をデフォルトに(screens.md §5)
7. **duplicate_same / duplicate_mirror の区別**: canonical_key 集合だけでは区別不能のため、
   判定済み集合は「canonical_key」と「生盤面文字列」の両方を保持する(game-core-api.md §2)
8. **効果音の発火責務**(サーバー送信 or クライアント自律)は S6 で最終決定(ws-messages.md §4 に明記)
9. **mode_select のフォーカス端ループ有無**は仕様どおり実装時調整(S4)
