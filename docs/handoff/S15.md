# S15 引き継ぎ: ディスプレイ視点の180°反転対応(HANOI_CAMERA_SIDE)

ユーザー報告「カメラはプレイヤーの反対側から撮影するが、プレイ時に画面の箱が奥面を
向いているように(プレイヤー視点と180°逆に)見えた」への対応。カメラ設置側を環境変数で
指定し、ディスプレイが常にプレイヤー視点で描画するようにした。

## 前提の整理(調査で確定した事実)

- マット座標系は四隅タグ(ID200-203)と印刷の対応**だけ**で決まり、カメラ位置に依存しない
  (`cv/geometry.py::calibrate` はホモグラフィ→姿勢復元で、どちら側から撮っても同じ座標系になる)。
- 3D画面は従来「マット手前=待機エリア側(three +z)」からの固定視点だった。よって
  **マットの待機エリアをカメラ側に向けて置く**と(=プレイヤーはマット奥側)、表示が
  プレイヤーから180°逆に見える。これが報告事象の原因。
- 箱のヨーは mod 90° でしか推定していないため、視点反転は面テクスチャ表示に影響しない。

## 完了したこと

- **環境変数 `HANOI_CAMERA_SIDE`**(`back`=カメラがマット奥側=既定 / `front`=カメラが
  待機エリア側)。運用前提「カメラは常にプレイヤーの反対側」のもと、`front` のとき
  ディスプレイが3D視点を180°反転してプレイヤー視点にする。
  - サーバー: `api/main.py::_camera_side()` が読み(不正値は警告+back)、`GameServer` 経由で
    ディスプレイ snapshot の `camera_side` として送出(`api/ws.py`)。状態機械には持たせない
    (ゲーム状態でなくデプロイ設定のため)。
  - フロント: `display/store.ts` が snapshot から `cameraSide` を取り込み、
    `three/BoardScene.ts::setCameraSide()` が Three.js カメラを ±z 側へ配置(ライトも対称に反転)。
    **座標データ・塔判定・マット座標系は一切変えていない**(視点だけ変える)。
    マットの A/B/C ラベルは front では上下逆に見えるが、物理と同じ見え方なので仕様。
- **CV側の設営ミス検知**: `cv/pipeline.py::_warn_if_side_mismatch()`。キャリブレーション
  成立時(初回)と保存済みキャリブレーション復元時に、実測カメラ位置
  (`cam_pos_mat` の y と マット奥行き/2 の比較)が設定と食い違えば警告ログ。
  `FramePipeline(expected_camera_side=None)` はチェック無効(既存テスト・モックにノイズを
  出さない)。実CV経路は `real.py::config_from_env` → `CvWorkerConfig.camera_side` で伝搬。
- **テスト**: `test_ws.py` +2件(front反映・不正値フォールバック+警告)+既定backのassert、
  `test_cv_pipeline.py` +3件(front側合成カメラ×back設定で警告 / front設定・未設定・
  back側カメラ×back設定で警告なし / 復元時の警告)。`PipeDriver` にカメラ注入引数を追加。
  フロント `store.test.ts` +2件(cameraSide反映・screenへの混入なし(toEqual完全一致で担保)・
  再snapshot上書き)。
- **ドキュメント**: `docs/operations.md` に「設営: マットの向きとカメラ側」を追記
  (基本はマット待機エリア=タグ202/203側をプレイヤーに向ける。frontにする場合の起動方法、
  警告ログの確認)。`.claude/launch.json` に `hanoi-cube-dev-front`(検証用)を追加。
- **表示検証(ブラウザ実施済み)**: `HANOI_CAMERA_SIDE=front` で塔枠が手前・待機箱が奥・
  A塔が右に反転表示されること、既定起動で従来表示(A左・待機手前・ラベル正立)のままで
  あることをモック盤面 `LMS//L` で確認。
- `make check` 通過(server 193 / frontend 105 / cloud 7)。

## 契約の変更(CLAUDE.md 規則1)

- **ws-messages.md §1/§3**: ディスプレイ snapshot payload に `camera_side: "back"|"front"` を
  追加。起動時に確定し変化しないため snapshot のみで伝える(専用メッセージなし)。
  コントローラ snapshot(§5)には含めない。Python写し(`api/messages.py` に `CameraSide`
  Literal)と TS写し(`contracts/ws.ts`)を同一セッションで更新済み。
- **cv-interface.md は変更していない**(判断): CvMessage の型・マット座標系は不変。
  反転はサーバーの座標出力ではなく表示視点のみで行うため、CV契約に影響しない。

## 要判断として選んだデフォルト(CLAUDE.md 規則3)

1. 反転の実現方式は「サーバーで座標を180°回す」ではなく「フロントのThree.jsカメラを
   反対側に置く」を選んだ。塔判定・エリア分類はマット印刷に物理的に固定されており、
   座標側を回すと判定と印刷枠が食い違うため。
2. `front` 時のマットラベル(A/B/C)は上下逆のまま表示する(プレイヤーが物理マットを
   見たときと同じ見え方=忠実)。読みやすさ優先で正立させたくなったら
   `textures.ts::buildMatTexture` に向き引数を足す拡張になる。
