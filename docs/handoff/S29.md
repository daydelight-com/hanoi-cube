# S29 引き継ぎ: 接地校正の実装(高さの系統誤差を起動時+コマンドで自動調整)

会期後(2026-08-22)の恒久対策。S24〜S26 で毎朝手作業になっていた「箱の高さの
系統誤差」(浮き・埋まり・接地判定のマージン侵食)を、サーバー側で自動推定・
補正する仕組みを実装した。

## 完了したこと

### 背景(なぜ必要か)

マット四隅タグは全て高さ0の同一平面にあるため、キャリブレーションは高さ方向の
スケール(焦点距離)を自己検証できない。会期中の実測では接地箱の底面zが
-31〜+13mm ずれ、接地判定(許容25mm)の抜けや3D表示の埋まりの原因になった。
水平方向は四隅で拘束されるため常に正確だった。

### 方式(ユーザー決定: 常時追従ではなく「調整ウィンドウ」方式)

「底面zが0近傍(|z|≤45mm)かつマット内の箱はマット面に静止している」を参照高さと
し、最下クラスタ(幅20mm)の中央値を系統誤差として推定、観測zから一様に引く
(相対値=積みギャップは不変)。推定は**調整ウィンドウ中のみ**行い、収束したら固定する:

- **起動時**: ウィンドウが自動で開き、接地箱が見えた更新150回
  (`GROUND_CAL_SETTLE_STEPS`、約30fpsで見えている約5秒分。途切れた時間は数えない)で
  確定。ログ「接地校正を確定した: 高さ補正 X.Xmm」
- **再調整**: `make ground-cal`(トリガーファイル `output/ground_autocal.request` を
  touch。稼働中のワーカーが約1秒以内に検知して開き直す。サーバー再起動不要)
- 運用手順: **マット上に箱を1つ以上きちんと置いた状態**で起動 or `make ground-cal`

当初は常時追従(照明ドリフト対応)で実装したが、プレイ中の観測(持ち上げ保持・
土台が一度も見えない積み箱)で補正が動きうる残余リスクがレビューで指摘され、
ユーザー判断で「調整の瞬間は状態を運用で保証できる」ウィンドウ方式に変更した。
誤学習防止は多層: トラッカー保持盤面で段1以上の箱を除外(遮蔽中も有効)/
参照中央値が上限(±30mm)超なら不採用 / 推定は生観測ベース(補正量が古くても
デッドロックしない)/ ウィンドウ外は完全固定。

### 変更ファイル

- `server/app/cv/ground_autocal.py`(新規): 推定の純ロジックと定数
- `server/app/cv/pipeline.py`: ウィンドウ制御(`_apply_ground_autocal` /
  `restart_ground_autocal`)、補正適用、`export/restore_calibration` に
  `ground_offset_mm`(旧形式は0・±30mmクランプ復元。起動時は復元値を初期値に再推定)
- `server/app/cv/tracker.py`: `elevated_box_ids()`(確定盤面で段1以上の箱)
- `server/app/cv/worker.py`: トリガーファイル監視(約1秒周期・起動時に残骸を消費)、
  補正量が2mm超動いたら10秒間隔でキャリブレーションを再保存(初回保存は補正≈0のため。
  復元起動で四隅が再びそろわない場合でも再保存される)
- `server/app/cv/real.py`: トリガーパスはリポジトリ直下 `output/` の絶対パス
  (ワーカーの cwd は `server/` のため相対だと `make ground-cal` と食い違う)
- `server/app/cv/real.py`: `HANOI_CV_GROUND_AUTOCAL=0` で無効化(縮退経路)
- `Makefile`: `ground-cal` ターゲット。`README.md`: コマンド・環境変数表に追記
- `server/tests/test_ground_autocal.py`(新規20件): 純関数(窓・クラスタ・除外・
  クランプ・符号反転からの再収束)、パイプライン統合(バイアス注入で収束→固定→
  restart で再収束、参照が途切れても未収束のまま確定しないこと)、保存/復元(旧形式・破損値クランプ)、トリガー消費、再保存判定

`make check` 全通過(server 228 / frontend 128 / cloud 12)。

## 契約からの逸脱・追加判断

- なし。cv-interface.md の `pos_mm`(底面中心)定義に対し、補正は定義への忠実度を
  上げる方向。エリア分類・積み判定の式は不変。
- 設計判断: 焦点距離そのものの補正は calibrate() の安定性への影響を避けて見送り、
  観測zへの一様オフセットとした(実測の誤差構造にはこれで十分)。

## 既知の問題

- ウィンドウ方式のため日中の照明ドリフトには自動追従しない。気になったら
  `make ground-cal`(箱を置いた状態で)を打つ運用。
- ウィンドウ中(起動直後の5秒間)に箱がマット上に1つもないと、最初の接地箱が
  見えるまで確定しない(見え次第5秒で確定するので実害はない)。
