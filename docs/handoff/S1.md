## 要判断(選んだデフォルトと理由)

1. **judge のシグネチャ矛盾**: game-core-api.md §2 の judge は `judged_keys`(canonical_key 集合)
   1引数だったが、canonical_key 集合だけでは duplicate_same / duplicate_mirror を区別できない
   (S0 要判断7「両方保持」とも不整合)→ **`judged_boards: AbstractSet[str]`(生盤面文字列集合)を
   第3引数に追加する契約修正を実施**。影響範囲: 契約md本体のみ(TS写しに game-core-api は無く、
   呼び出し側の状態機械は未実装)。**S2 は judge に両集合を渡すこと**
2. **duplicate の min_moves**: 契約は「クリア可能時の最短手数」とだけ規定 → duplicate_same /
   duplicate_mirror(いずれもクリア可能)でも min_moves を返す(points は 0)
3. **min_path の一意性**: 最短手順が複数ある盤面では BFS の探索順(塔 A→B→C)で定まる1本を
   テーブルに固定。テストは「手順が合法で長さ=min_moves かつクリア条件を満たす」ことを検証し、
   特定の手順には依存しない
