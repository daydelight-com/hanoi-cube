# S24 引き継ぎ: 本番前日のキャリブレーション不成立の顛末と本番朝チェックリスト

本番前日(2026-08-20 夕方)の設営中に発生した「キャリブレーション不成立(24mm棄却)」
「箱が全て浮いて表示される」障害の切り分けと復旧の記録。**コード・契約・ドキュメントの
変更は一切なし**(本メモの追加のみ)。運用で解消した。

## 完了したこと

### 症状と原因の特定

1. **再投影誤差 24mm で恒常的に棄却**(閾値9mm)。診断ログの想定→実測は
   右側タグ2枚が約+17mm外側、奥側タグ2枚が約-13mm内側という系統パターン。
   S9 記録済みの印刷歪み(+6/-3mm)では説明できない大きさだった。
2. **「キャリブレーション=済」なのに箱が全て大きく浮く**。「済」の正体は起動時に
   読み込まれる `output/cv_calibration.json` の保存値で、**前日のカメラ位置で成立した
   古い解**だった。カメラを動かした後もこの解で箱位置を計算するため、焦点距離・姿勢の
   ずれが箱の距離推定に乗り、全箱が一様に浮いた(S9「焦点距離の自己推定は敏感」の
   実機再現)。

根本原因は**設営でカメラ位置が変わったこと**。マット・タグの物理配置は無罪。

### 復旧手順(再現可能)

1. マット四隅タグ4枚の上の遮蔽物(箱・手)をどけ、**4/4が同時に見える状態を数秒作る**。
   1秒ごとの自動再キャリブレーションが新しいカメラ位置で成立し、**メモリ上の**古い解を
   上書きする。今回はこれで復旧した。
   注意: `output/cv_calibration.json` への保存は**1ワーカープロセスにつき初回成立の
   1回だけ**(`worker.py` の `calibration_saved`)。カメラを動かした後の再成立はファイルに
   反映されないため、確実を期すなら json を削除してサーバーを再起動する(下記チェック
   リストの手順を正とする)。
2. カメラを掴む別プロセスを排除する。今回 `make camera-check`(cv_poc.py --show)が
   サーバーと同時にカメラ0を開いており、17:31 に CVワーカーが一度自動再起動した。
   競合が疑わしい。**camera-check はサーバー起動前に済ませて閉じる**こと。

### 検証(実測値)

- 成立した焦点距離は再起動をまたいで 1484 → 1446 → 1430px と同じ帯で安定。
  このカメラ(1920x1080)の正常値とみてよい(水平画角換算 約67°)。
  ※S9 の「2300px」は合成実験の値であり、このカメラの基準にしないこと。
- `/ws/display` に直接接続して実測: 塔Bに置いた大箱が
  `pos_mm ≈ (207.5, 185.6, +1.6)`、z ブレ 1.4〜1.8mm、`area="B"` / `level=0`、
  盤面 `"/L/"` で正しく成立。浮きは解消。
- 検証スクリプトは使い捨て(scratchpad)。要点: `websockets` で
  `ws://localhost:8000/ws/display` を数秒購読し `boxes` の `pos_mm[2]`(底面中心z)を見る。
  マット上で静止した箱の z が 0±15mm 程度なら健全。

## 既知の問題

- `output/cv_calibration.json` は「カメラ・マット固定」前提の高速起動用。設営を変えた
  直後は古い解のまま動き出すため、必ず四隅を見せ直す必要がある(下記チェックリスト)
- 保存は1ワーカープロセスにつき初回成立の1回だけ。**日中の再キャリブレーションは
  ファイルに反映されず**、その後ワーカーが再起動すると移動前の解に戻る(四隅を見せ
  直せばメモリ上は再度復旧する)。カメラを動かした日は json 削除+再起動が確実
- 復元起動時、「キャリブレーション更新: 焦点距離=…px」は DEBUG 扱いで INFO ログに
  **出ない**(`pipeline.py` は2回目以降の更新を DEBUG にする)。焦点距離を確認したい
  ときは json を削除してから起動する(初回成立として INFO に出る)か、
  `output/cv_calibration.json` の `k[0][0]` を直接見る
- CVワーカーは停止すると自動再起動される(起動後3秒間は再起動を抑止=即死ループ対策。
  3秒待ってから再起動する意味ではない)。再起動自体は正常系だが、頻発する場合は
  カメラの取り合い(camera-check 併走等)を疑う
