# S6 引き継ぎ: 効果音+通し磨き

## 完了したこと

- `frontend/src/sfx/` — Web Audio 効果音一式(仕様§5.12):
  - `engine.ts` — 合成エンジン。矩形波・三角波+ゲインエンベロープ、打撃系はノイズバッファ
    (音源ファイルなし)。全15 SfxId のレンダラーを実装。judge_success は得点に応じて
    アルペジオを4〜8音に拡張(`successNoteCount`)+コイン音。マスターゲイン 0.22。
    `install()` で pointerdown / keydown による AudioContext の遅延アンロック
    (§5.12 iOS/Safari 制約: iPad はセッション開始時の初回タッチ、ディスプレイは Mac の初回クリック)。
    `play()` は音声出力の有無に関わらず発火ログ(`playedIds`、上限500)へ記録し、
    `window.__sfxPlayed` / `window.__sfx` として公開(無人E2Eの代替検証+実機スピーカーテスト用。
    コンソールで `__sfx.unlock()` 後に `__sfx.play('fanfare')` などで単発再生できる)
  - `displaySfx.ts` — 受信メッセージ+直前状態から鳴らす音を導出する純関数
    `deriveDisplaySfx`。遷移表・ctx差分・countdown/timer/judge/name/lang を網羅
  - `controllerSfx.ts` — `deriveControllerSfx`(flash→pad_flash、sfx→無条件再生)
- 配線:
  - `DisplayApp` — socket onMessage で導出→再生。React の描画バッチに依存しないよう
    `sfxStateRef` にリデューサをもう一度畳み込み、メッセージ単位で prev→next を追跡
  - `ControllerApp` — pad_button を押下ローカル再生(3ボタン+かんりょうボタン+開発用キーボード)、
    受信メッセージは deriveControllerSfx 経由
  - `IdleRankingScreen` — せり上がりに同期して rank_tick(1行=1秒)、1位到達でファンファーレ。
    タイミングは `idleRankingTiming.ts` の `idleRankingTickTimes`(サーバーの IDLE_RANKING_* と同式)
- `docs/contracts/ws-messages.md` §4 — **発火方式の決定表を追記**(下記)
- E2E `frontend/e2e/full-play.mjs` — 通しプレイの最後に発火ログを検証するステップを追加。
  台本から回数が一意に決まる音は厳密比較(count=3, go=1, timeup=1, tick10=9,
  judge_success=2, judge_dup=1)、タイミング依存の音は1回以上で検証
- テスト: フロント計94件(+28: displaySfx 導出の全分岐、controllerSfx、エンジンの発火ログと

## 契約からの逸脱・追加判断

- **ws-messages.md §4 に発火方式の表を追記**(S6 に委ねられていた決定。CLAUDE.md 規則1):
  **全効果音をクライアント自律発火**とした。理由: サーバーは sfx を一切送っておらず、
  判定・遷移・タイマーの全情報が既存メッセージから確定的に導出できる。サーバー変更ゼロで
  済み、ガード外の操作はサーバーが何も送らない=音も出ない、が自然に成立する。
  `sfx` メッセージは将来の上書きチャネルとして残置(受信したら無条件再生)。
  Python/TS の写しの変更はなし(型は既存のまま)

## 要判断(選んだデフォルトと理由)

1. **遷移音の割り当て**(契約表の注記にも記載):
   - qr→idle_title は `decide`(「けっていボタンで タイトルへ」の確定操作として、
     result→ranking→qr と一貫させた。「閉じる」感を出すなら back に変えるだけ)
   - mode_select→game_countdown は無音(直後の count「3」がフィードバックを兼ねる。
     decide を重ねると濁るため)
   - idle_title⇄idle_ranking は無音(enter とタイムアウトが display 側で区別できない。
     待機ループが5秒ごとに鳴るのを避ける意図もある)
2. **key_touch はディスプレイ側のみ**(name ミラーの変化時)。iPad 側はOSキーボード自体の
   操作感があるため重ねない
3. **result の input_mode 切替(再入力/かんりょう)は decide**、focus 移動は cursor
4. **待機ランキングの rank_tick は行数27超でクランプ**されたスクロールでも1秒間隔のまま
   (サーバーのタイムアウト式と同じ時間軸を維持)
