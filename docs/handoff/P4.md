# P4 引き継ぎ: 判定・得点・ゲーム画面

計画書 `docs/pyxel_app_development_plan.md` §4 の P4。`pyxel_app/` に判定集計(`session.py`)、画面の骨組み(`screens/`)、
ゲーム画面(HUD / 3-2-1-GO / JUDGE / フィードバック)、リザルト(仮)とタイトル(仮)を追加し、ブラウザで 60 秒のプレイが成立して得点が入る。
既存コード(`server/` `frontend/` `cloud/` `docs/contracts/`)とランタイム(`pyxel_app/runtime/`)は変更していない。

## 完了したこと

### `pyxel_app/session.py`(仕様書 §5、§6.4。Pyxel 非依存)

- `GameSession(table)`: `start(now)` → COUNTDOWN(3 秒)→ PLAYING(60 秒)→ FINISHED。時刻は `time.monotonic()` 秒を呼び出し側が毎回渡す
- `judge(board, now)` → `Judgement` か `JudgeRejection`(NOT_PLAYING / TIME_UP / COOLDOWN / ILLEGAL_BOARD)。
  集計は `StateMachine._apply_judgement()` の写し(scored: 加点+両集合、unclearable: fail_count+1、duplicate_*: 両集合のみ)。
  クールダウン 0.5 秒(`JUDGE_COOLDOWN_MS` と同値をテストで照合)。拒否された判定はクールダウンを延長しない
- タイムアップ境界: `now < deadline` なら有効、`now >= deadline` は TIME_UP(既存 `_button_game_play` の `now_ms >= start + GAME_MS` と同じ)
- `poll(now)` が COUNTDOWN_TICK / GO / TIME_UP を 1 回ずつ返す(効果音トリガ)。処理落ちで飛んでも GO / TIME_UP は必ず出る
- 表示用: `countdown_value`(3→2→1)、`show_go`(GO 後 1 秒)、`remaining_display`(切り上げ `M:SS`)、`in_warning`(残り 10 秒)
- リザルト用: `records`(`JudgeRecord`: seq / board / elapsed_sec / result / points / min_moves)、`best`(最高得点盤面、同点は先)

## 要判断(選んだデフォルト)

1. **3D ビューは全画面のまま、HUD(上 16px)と下段ボタン(隅)を重ねる**。仕様書 §3.4 の 320×184 ビューポートにするとマットが 0.77 倍に縮み
   S 箱(30mm)が掴みにくくなる。P3 のカメラ・ピッキング検証もそのまま生きる。JUDGE ボタン(x≥258, y≥212)は待機 L3 の右上角(270,218)と
   数 px 重なるが、ボタンが手前に描かれるので操作上の問題はない(P3 handoff の「HUD は上 24px 以内か右上に寄せる」に従った)
2. **ボタンは mouse down で反応**(mouse up ではない)。タイムアップ直前のクリックを「押下時刻」で判定する仕様(§3.4)と揃えた
3. **ボタンで始まった押下はドラッグに流さない**(`GamePlay._captured`)。JUDGE ボタンの下に箱があっても掴まない
4. **入場時に既に押されていたボタンは無視**(`ClickEdge` / `GamePlay` とも初期 `_held=True`)。非ヘッドレス Chrome で 1 回、
   Pyxel web の「CLICK TO START」のクリックがそのままタイトルの START に当たってゲームが始まった。再現条件は未確定だが防御として入れた
5. **タイムアップ時にドラッグ中なら元位置へ戻し、音は出さない**。終了後の入力は一切受け付けず、次フレームでリザルトへ
6. **「GO!」はプレイ開始後 1 秒表示**(判定可否には無関係。GO と同時の判定は有効)
7. **duplicate の `dup_of_seq` は持たない**(Pyxel 版は記録画面が無い)。`JudgeRecord` には seq / board / elapsed_sec / result / points / min_moves
8. **Enter キーで判定**(§3.1 の補助)。Esc=タイトルは未実装(P5 のタイトル実装時に)
9. **仕様書 §5 要判断 #7(`_apply_judgement` の共有)は切り出していない**。`session.py` に同じ規則を写し、照合テストで守る
10. **カウントダウン中の残り時間表示は「1:00」固定**、終了後は「0:00」
11. リザルトの BEST は「得点した判定の中で最大。同点は先」(`GameSession.best`)
12. `draw.big_text` は内蔵 4x6 フォントの拡大(5 倍でカウントダウン、4 倍でフィードバック、3 倍でタイトル)。日本語フォントでの HUD は P5

## 既知の問題

- **非ヘッドレス Chrome での CDP 検証は実機マウスの干渉を受ける**。本セッションでも、人が在席した時間帯に CDP の操作と無関係に
  箱が移動し・画面がタイトルへ戻る現象が出た(P3 の「1 回だけドラッグが無反応」も同根と推定)。
  `--headless=new` なら干渉が無く、rAF も止まらない。**今後の無人検証はヘッドレスを推奨**(手順は下記)
- 前セッションから残っていた `:8081` の `python -m http.server`(PID 43075)はセッション再開後に消えていた。
  本セッションでは `cd site && python3 -m http.server 8081` を自分で起動した(終了時に停止)
- 非ヘッドレスで CDP の WebSocket が 1 回切れた(`Unsettled top-level await`)。再接続で復旧。原因未特定

## 検証環境(無人向け手順)

```bash
make pyxel-site
(cd site && python3 -m http.server 8081 &)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --remote-debugging-port=9333 \
  --user-data-dir=<scratchpad>/chrome-headless --window-size=1000,800 --no-first-run "http://localhost:8081/?t=$(date +%s)"
```

Node 22 の組み込み WebSocket で `curl localhost:9333/json` の page ターゲットへ接続し、canvas の `getBoundingClientRect()` から
画面座標(320×240)→ page 座標へ変換して `Input.dispatchMouseEvent`、`Page.captureScreenshot` で確認する
(スクリプトは scratchpad に置いたため残っていない。操作列は JSON の `[["click",x,y],["drag",x,y,x2,y2],["wait",ms],["shot",path]]`)。
Pyodide のロード後に「CLICK TO START」を 1 回クリック → タイトル START(160,162)→ 塔 A/B/C の画面座標 (104,101)/(160,101)/(216,101)、
初期配置の L1 (97,189)・M1 (86,141)・S1 (191,143)、JUDGE (287,224)、TITLE (26,224)、リザルト RETRY (104,176)・TITLE (216,176)。
積んだ箱の top は画面上でもっと上に来る(`LMS//` の S1 は (78,42))ので `BoardScene.project(layout.box_center(...))` で求める。
