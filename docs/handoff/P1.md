# P1 引き継ぎ: 足場・ランタイム固定・配信(Pyxel Cube 版)

計画書 `docs/pyxel_app_development_plan.md` §4 の P1。`pyxel_app/` の骨組み、固定ランタイム、静的サイト組み立て、
GitHub Pages 配信、ネイティブ wheel の Release 配布、日本語フォントの選定までを行った。
既存コード(`server/` `frontend/` `cloud/` `docs/contracts/`)は変更していない。

## 完了したこと

### 足場(`pyxel_app/`)

- `main.py`: サンプル c01 相当の回転キューブ(320×240、`fps=60` 明示)。起動時に `app.core` を import して
  `load_table()` → `judge("LMS//", ...)` まで通し、画面左上に `core OK (512 boards, LMS// -> 21pt)` を表示。
  下端に `pyxel.Font` で「ハノイキューブ」を描画。`sys.path` は仕様書 §2.2 の通り `_core/` → `../server` の順に補完し、
  どちらにも無ければ `SystemExit` で明示エラー
- `pyproject.toml`: server と同じ ruff / mypy strict / pytest 設定。`pyxel==3.0.0` は `[tool.uv.sources]` で
  GitHub Release の macOS arm64 wheel を指す(マーカーで macOS arm64 限定。`uv sync` だけで入る)。`uv.lock` をコミット
- `assets/umplus_j10r.bdf` + `LICENSE_umplus_j10r.txt`(後述)
- `tests/test_scaffold.py`(8 件): ランタイム 5 種の存在、`pyxel.js` が同梱 wheel を指すこと、`index.html` が CDN を使わないこと、
  フォントに「ハノイキューブ」の全グリフがあること、`main.py` の `sys.path` 補完(成功/失敗)、`build_pyxel_site.py` の生成物検証
- `web/index.html`: `runtime/pyxel.js` を相対パスで読む。`<pyxel-play root="." name="hanoi_cube.pyxapp" packages="pydantic">`

### 固定ランタイム(`pyxel_app/runtime/`)

- `~/workspace/pyxel-cube/wasm/` から 5 種(`pyxel.js` / `pyxel.css` / `import_hook.py` / `images/`×7 / wheel 5.3MB)をコピーしてコミット。
  `VERSION.md` に元コミット `f731329`・ビルド環境を記録
- ブラウザのコンソールで `Launch Pyxel 3.0.0 with Pyodide 314.0.2` を確認(CDN は読んでいない)

### 配信

- `scripts/build_pyxel_site.py`(Python、Windows でも動く): `build/hanoi_cube/` に `main.py` / `assets/` / `server/app/core` のコピー
  (`_core/app/core`、`precompute.json` 込み)を集めて `pyxel package` → `site/`(`index.html` / `runtime/` / `hanoi_cube.pyxapp` / `.nojekyll`)。
  必須ファイルが欠けていれば非 0 で終了。**`pyxel_app/` をそのまま package すると `runtime/`(5MB)や `tests/` まで zip に入る**ため
  staging ディレクトリ方式にした。`.pyxapp` は 157KB
- `Makefile`: `check-pyxel`(`check` に組み込み済み)、`pyxel-site`、`pyxel-serve`(`:8081`。Firestore エミュレータの 8080 と分離。`PYXEL_PORT=` で変更可)
- `.github/workflows/pyxel-pages.yml`: `main` への push(`pyxel_app/**` `server/app/core/**` `scripts/build_pyxel_site.py`)と手動で
  `pip install pyxel`(PyPI 版。zip を作るだけ)→ `build_pyxel_site.py` → `upload-pages-artifact` → `deploy-pages`
- GitHub Pages を API で有効化し、ソースを **GitHub Actions**(`build_type=workflow`)に設定済み。URL `https://daydelight-com.github.io/hanoi-cube/`
- `.claude/launch.json` に `pyxel-site`(`make pyxel-serve`、port 8081)を追加

### ネイティブ wheel(macOS Apple Silicon)

  GitHub Release **`pyxel-cube-runtime-2026-08-23`** に WASM wheel と一緒に添付。README と `pyproject.toml` がこの URL を参照

### 要判断 #3(pydantic のロード時間)の実測

ローカル配信・M1 Mac / Chrome: クリック後に pydantic 系 5 wheel(pydantic / pydantic_core / typing_extensions / annotated_types /
typing_inspection、合計約 1.9MB、jsDelivr の Pyodide CDN から取得)の取得+展開が **約 2.1 秒**、その後 `.pyxapp` 取得と起動。
Pyodide 本体(約 6MB)のロードは別途約 1 秒(キャッシュ無し)。**pydantic を読み込む方針を確定**(仕様書 §11 #3 を更新)。
回線 50Mbps なら初回 5 秒以内(§10)は達成できる見込みだが、公開 URL での実測は P6 で行う。

## 契約からの逸脱・追加判断

- 契約変更なし。既存コードの変更なし
- `pyproject.toml` の `pyxel` 依存は **macOS arm64 限定のマーカー付き**。それ以外の環境では pyxel が入らず、`mypy` は
  `ignore_missing_imports` で pyxel を Any 扱いする(型チェックの厳しさが環境で変わる。Windows wheel を Release に載せた時点で
  `[tool.uv.sources]` に行を足す)
- 仕様書 §8.1 の `requirements-dev.txt` 方式は採らず、`pyproject.toml` + `uv sync` に統一(仕様書 §8.1.1〜8.1.3 を更新)
- ローカル配信ポートを 8080 → 8081 に変更(Firestore エミュレータと衝突。計画書 §5・仕様書 §8.1.3 を更新)
- `pyxel package` は PyPI 版(2.9.x)でも cube 版でも zip 形式は同じ前提で CI は PyPI 版を使う(仕様書 §7.2 通り)。
