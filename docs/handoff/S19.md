# S19 引き継ぎ: 記録画面のレトロ化・アップロード誤爆修正・実CV既定化

ユーザー報告2件への対応セッション。(1)「記録画面のデザインがゲーム画面と違う」
(2)「記録が『じゅんびちゅう』のまま = Firestoreに入っていない」。後者の調査で
重大な設定事故(下記)を発見し、恒久対策として設定の既定値を作り直した。

## 完了したこと

### 1. 記録画面をゲーム画面のレトロテーマに統一(仕様§5.10 / §5.1)

- `cloud/record/src/index.css` / `App.css`: display の `retro.css` と同じ配色
  (CRT暗緑 `#060d06`・ネオン `#438532` 基調)・グロー・点滅・枠(retro-frame相当)・
  スキャンラインオーバーレイ(`App.tsx` に div 追加)。判定バッジは判定演出と同配色
  (得点=金 / 失敗=橙赤 / 重複=ネオン緑)。
- `cloud/record/index.html`: DotGothic16 を Google Fonts で配信(来場者端末には無いため)。
- `BoardView.tsx`: 箱をゲームの3Dテクスチャと同一に(`textures.ts` の SIZE_COLOR:
  大=#c0392b / 中=#438532 / 小=#2e6da4、黒縁、「大1」形式の白ラベル)。台はマット同系
  (暗緑地+ネオン枠)。シミュレーションの移動箱は `#b9ff8e` 縁でハイライト。
- **本番デプロイ済み**: `cd cloud/record && VITE_FIREBASE_PROJECT_ID=hanoi-cube
  VITE_FIREBASE_API_KEY=<公開webキー。既存dist/デプロイ済みJSから取得可> npm run build`
  → `cd cloud && firebase deploy --only hosting`。実プレイ記録で表示確認済み。

### 2. 障害対応: プレイ記録が別プロジェクトの Firestore に書き込まれていた

- **原因**: 開発者シェルの `~/.zshrc` に他案件の
  `GOOGLE_APPLICATION_CREDENTIALS=~/orgaster-staging-credentials.json` が常設されており、
  アップローダが「標準ADCも受け付ける」仕様だったため **orgaster-staging プロジェクト**の
  Firestore `plays` に3プレイを書き込み、SQLite 上は uploaded=1 になっていた。
  記録画面(hanoi-cube を読む)は永遠に「じゅんびちゅう」。
- **復旧**: `UPDATE plays SET uploaded=0` + 正しい認証で再起動 → 本番へ再送済み。
  実プレイ(8/10 ｺﾔﾏｧ 117点)の記録画面表示を確認。
- **未処理**: orgaster-staging 側に残った `plays` 3ドキュメントの削除はユーザーが
  コンソールから行う(こちらからは触らない)。

### 3. 恒久対策: 設定なしで正しく動く既定値(server)

- `app/cloud/uploader.py`: `resolve_credentials_path()` を新設。優先順は
  **`HANOI_FIREBASE_CREDENTIALS`(明示) > リポジトリ直下 `service-account.json`(自動検出)**。
  **汎用ADC(`GOOGLE_APPLICATION_CREDENTIALS`)は意図的に無視**(上記事故の根絶。
  回帰テスト `test_generic_adc_is_ignored`)。`make dev` だけで本番アップロードが有効になる。
- `app/cloud/reset.py` / `demo_play.py`: 接続先表示・エラーメッセージを同ロジックに統一。
  `docs/operations.md` の手順から環境変数指定を削除。
- `tests/conftest.py`: 開発機に実在する `service-account.json` がテストへ漏れないよう
  `default_credentials_path` を存在しないパスに差し替え(autouse)。

### 4. 実CVを既定化(`HANOI_CV=real` の指定を不要に)

- `app/api/main.py` `_make_cv()`: 既定 real、`HANOI_CV=mock` でモック。不正値は警告して real。
- モックは縮退経路として維持(CLAUDE.md 規則6)。`/api/mock/*` は実CV時に既存ガードで4xx。
  テストは conftest で `HANOI_CV=mock` を常設。
- `.claude/launch.json`: `hanoi-cube-dev-real` → `hanoi-cube-dev-mock` に置き換え
  (既定が real になったため)。

## 契約からの逸脱・追加判断

- 契約(docs/contracts/)の変更なし。
- 「ADCを無視する」は S12 の「標準ADCも受け付ける」判断の**撤回**。理由は上記事故
  (他案件の認証で無関係プロジェクトへ書き込み)。明示指定(`HANOI_FIREBASE_CREDENTIALS`)は
  引き続き有効なので、ADCでしか運用できない環境が現れたらそのとき再検討。
- 実CV既定化により、カメラの無いマシンで素の `make dev` を実行すると実CVの初期化が
  失敗する。開発でモックを使う場合は `HANOI_CV=mock`(launch.json の
  `hanoi-cube-dev-mock`)を使うこと。

## 既知の問題

- **開発MacのディスクフルによりCodexレビュー未実施**(ENOSPC でエージェント起動不可)。
  S19の差分は local-code-review(自己精査)+ security-review のみ実施(指摘0件)。
  次セッションの super-review でまとめて見直すこと。
- ディスク残量が依然少ない(解放後3GB)。ブース本番前にさらに確保を推奨
  (SQLite WAL が書けなくなるとプレイ記録保存自体が落ちる。今回発生済み)。
- 記録画面を過去に開いた端末はブラウザキャッシュで旧デザインが出ることがある
  (リロードで解消。来場者は初見なので影響なし)。

## 次セッションへの注意

- 起動は素の `make dev` で「実CV+本番アップロード」。モック開発は `HANOI_CV=mock`。
- 本番前のデータリセットは `docs/operations.md` の手順(環境変数不要になった)。
- 記録画面のビルドには `VITE_FIREBASE_PROJECT_ID` / `VITE_FIREBASE_API_KEY` が必要
  (上記§1のコマンド)。未指定ビルドは「せっていちゅう」表示になるので注意。
