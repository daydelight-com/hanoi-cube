# S17 引き継ぎ: 旧iPad(iOS 15)でコントローラが真っ白になる問題の修正

ユーザー報告「一部のiPadで /controller が表示されない(Chromeで
ERR_SSL_PROTOCOL_ERROR → 解消後は真っ白)」への対応。原因は2段階あった:

1. **ERR_SSL_PROTOCOL_ERROR**: iPad側ブラウザが http を https に自動格上げしていた
   (ChromeのHTTPSファーストモード等)。端末設定の変更で解消(コード変更なし)。
2. **真っ白**: iOS 15.7 の WebKit は **static class blocks(ES2022, Safari 16.4+)**
   非対応。three.js(依存バンドル)内の該当構文がモジュールパース時に SyntaxError となり
   何も描画されない。エラーは window.onerror にも乗らないため画面上は無症状だった。

## 完了したこと

- **frontend/vite.config.ts**: 配信/ビルドの変換ターゲットを ES2020 相当に固定。
  **Vite 8 は Rolldown/Oxc ベースのため `esbuild` / `optimizeDeps.esbuildOptions` は
  無視される(型は通るが効かない)**。正しくは:
  - `oxc: { target: 'es2020' }`(ソース変換)
  - `optimizeDeps: { rolldownOptions: { transform: { target: 'es2020' } } }`(依存バンドル)
  - `build: { target: 'es2020' }`(本番ビルド)
    ターゲット変更後は `node_modules/.vite` の削除(または `--force`)が必要な場合がある。
    実際、設定変更だけでは three.js の再バンドルに反映されなかった。
- **frontend/index.html**: 起動失敗をコンソールなしで確認できる仕掛けを常設
  (ES5のみで記述)。`#boot-marker` が5秒後も残っていれば動的importで読み直し、
  失敗理由(SyntaxError等)を画面上部に赤帯で表示する。未捕捉エラー/未処理rejectionの
  画面表示も追加。ブース当日、来場者端末での切り分けに使える。
- **frontend/public/diag.html**: 端末診断ページを追加(ES5のみ)。UserAgent、
  モダン構文の対応状況(optional chaining / class fields / static blocks 等)、
  WebSocket接続、module script 対応を画面に判定表示する。
  当日は `http://<サーバーIP>:5173/diag.html` を開かせるだけで端末側の切り分けができる。
- 検証: 配信モジュールグラフ全54モジュールを機械検査し、static blocks・正規表現
  後読み・import属性・v フラグ正規表現が残っていないことを確認。実機の iOS 15.7 iPad で
  コントローラの表示をユーザーが確認済み。通常ブラウザでの表示・型チェックも確認。

## 運用メモ(ブース当日向け)

- **ターゲットを下げても救えるのは「構文」だけ**。新しいランタイムAPI
  (`structuredClone` 等)はポリフィルされない。今後 iOS 16.4 未満の端末で真っ白に
  なったらまず diag.html → 赤帯のエラー文言を確認する。
- iPadで「安全に接続できません」が出たら: Chromeの「常に安全な接続を使用する」を
  OFF、履歴削除のうえ `http://` を手入力。MDMプロファイルでHTTPS強制されている
  端末は回避不可(その場合は別端末を使う)。
- **開発機の localhost:5173 は別プロジェクト(kishi-meikan)の Vite が同居し得る**。
  hanoi 側は `host: true`(全インターフェース)、他方は localhost のみで待ち受けるため
  「localhost では別物・LAN IP では hanoi」という紛らわしい状態になる。検証は
  `127.0.0.1:5173` か LAN IP で行い、`lsof -nP -iTCP:5173` で同居を確認すると早い。

## 既知の問題・次セッションへの注意

- index.html の起動失敗フォールバックは `/src/main.tsx` を動的importする。
  本番ビルド(dist配信)ではこのパスは存在しないが、マウント成功時はマーカーが
  消えて発火しないため無害。dist配信で起動失敗した場合はエラー文言が
  「モジュールが見つからない」系になり実際の原因とずれる点だけ留意。
- 本番も同じ旧iPadを使うなら追加対応不要(`build.target` にも効いている)。
