# P6a 引き継ぎ: Three.js 版アートワークのドット化テクスチャ導入

ユーザー要望「Three.js の時に使用していたような画像を Pyxel 版でも使いたい。スタイルが崩れるなら
ドット化した画像で」を受け、`frontend/public/textures/` のアートワーク(箱 3 種 + プレイマット)を
ドット化して Pyxel 版の 3D 盤面に貼った。契約(`docs/contracts/`)・既存コード(`server/` `frontend/`
`cloud/`)・ランタイム(`pyxel_app/runtime/`)は変更していない。

## 完了したこと

### 変換スクリプト `scripts/make_pyxel_textures.py`(新規)

- 箱 3 種は 64x64、マットは 256x181(実寸 420x297mm と同比)へ縮小し、各画像 16 色へ減色
  (ディザなし)。使った全色(計 64 色)を `palette.json` に出力
- 出力先 `pyxel_app/assets/textures/`(計約 10KB)は**コミット済み**。再生成が必要なのは
  アートワーク差し替え時だけ: `uv run --with pillow python scripts/make_pyxel_textures.py`
  (Pillow は実行時依存に含めない)
- 32x32 も試したがロゴ・CUBE 文字が潰れるため 64x64 を採用

### 読み込み `pyxel_app/scene/textures.py`(新規)

- `load()` が palette.json の色のうち未登録のものだけを `pyxel.colors` の末尾へ追加(冪等)して
  から PNG を読む。Pyxel の `Image.from_image` は現行パレットへの最近色量子化なので、色が既に
  あることで**完全一致=無劣化**になる
- **注意: `from_image(include_colors=True)` はパレットを丸ごと差し替える破壊的動作**
  (追加ではない。本セッションで実測)。使わないこと
- パレットは 16 → 80 色になる。既存 16 色の並びは不変(UI は番号参照のため)。
  `load()` は Shading 生成より前に呼ぶ必要があり、`main.py` で `BoardScene` 生成の直前に呼ぶ
- 画像一式が無い環境では空の `Textures` を返し従来の単色描画に縮退(モックCV と同じ縮退思想)

### 盤面への適用 `pyxel_app/scene/board_scene.py`

- `BoardScene(colors, w, h, textures)` に `Textures` を追加(省略可。テストは従来どおり動く)
- `BoxNode`: テクスチャがあれば `Node.box(mat, size, image)` で貼る(輪郭線は従来どおり)。
  無ければ従来の単色
- `MatNode`: マット直方体にマット画像を貼る(box は上面に画像全面が正立で貼られる)。
  テクスチャ時は**塔マーカーの塗りつぶしを描かない**(アート側に塔の枠があるため)。
  A/B/C ラベルとスロット枠・ハイライトは引き続き描く

### テスト `pyxel_app/tests/test_textures.py`(新規、5 件)

## 要判断(選んだデフォルト)

1. **ロゴは全面貼り**。pyxel.cube の box プリミティブは 6 面すべてに同一 UV(画像全面)を貼るため、
   Three.js 版の「ロゴは面 1・6 のみ」(textures.ts)は再現しない。L/M はロゴ入り素材を全面に、
   S はロゴなし素材(実物どおり)。面別に分けるにはカスタム Mesh + アトラスが必要で、
   320x240 では効果に見合わないと判断
2. **タグ(AprilTag)は箱の面に貼らない**。64x64 では潰れてノイズになる(マットの四隅タグは
   一枚絵に含まれるのでそのまま)
3. **縮退時の単色(BOX_COLORS: L=青系/M=緑系/S=黄系)は従来のまま**。アートの実色
   (L=緑/M=オレンジ/S=白)とは違うが、縮退経路の見た目変更は別判断とした
4. マットのテクスチャ時も **A/B/C ラベル・スロット枠・ハイライトは描画継続**(操作情報のため)。
   塔マーカーの塗りつぶしのみ非表示
