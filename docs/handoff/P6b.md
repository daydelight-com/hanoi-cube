# P6b 引き継ぎ: ルール説明画面への図版導入

ユーザー要望「Pyxel 版のルールがわかりづらい。Three.js 版のように図を入れた説明にしてほしい」を受け、
ルール説明画面(仕様書 §3.3)の 5 ページ全部に図版を追加した。契約(`docs/contracts/`)・既存コード
(`server/` `frontend/` `cloud/`)・ランタイム(`pyxel_app/runtime/`)は変更していない。

## 完了したこと

### 図版データ+レイアウト `pyxel_app/screens/rule_figures.py`(新規、Pyxel 非依存)

- frontend の `display/screens/ruleFigures.ts`(Three.js 版ルールダイアログの SVG 図版)を
  320×240 向けに移植。データ構造(コマ/塔/○✕/移動矢印/つなぎ記号/バッジ/A/B/C ラベル)と
  レイアウト計算(コマ幅・オフセット・箱座標)を frozen dataclass + 純関数で持つ
- 5 ページ構成は文言(`i18n.RULE_PAGES`)と同順: あらまし(積む→はんてい→+18)/ つみかた ○✕ /
  うごかしかた ○✕(移動元の箱に色枠+弧の矢印)/ クリア(さいしょ ⇄ 左右反転、鏡線)/
  得点式バッジ(6こ×3て=18)
- 座標は図版ローカル。`MAX_FIGURE_W = 296`(パネル幅 304 − 余白)に全図版が収まる

### 描画 `pyxel_app/screens/rules.py`

- 見出し帯の下に図版(y=33〜)、本文 3 行を下部(y=142〜、行送り 14)へ移動。図が主役・文言が補助
  (frontend `RuleDialogScreen.tsx` と同じ考え方)。ボタン・ページインジケーター・遷移ロジックは不変
- 箱の色は**盤面テクスチャの実物色**に合わせた: 大=緑(11/縁は基調色 3)・中=橙(9/縁 4)・
  小=白(7/縁 12)。Three.js 版図版の小=水色から変えたのは、Pyxel 版の実箱(P6a のテクスチャ)が
  白のため(図と実画面の一致を優先)
- ○=緑の二重円、✕=赤、移動矢印は 2 次ベジェの折れ線近似+矢じり(NG は赤)、
  クリアの図は破線の鏡線+⇄

### テスト `pyxel_app/tests/test_rule_figures.py`(新規、10 件)

図版数=ページ数(日英)/ 全図版が MAX_FIGURE_W 内 / コマ間の隙間とオフセット整合 / 縦レイアウト /
塔は 3 箱まで / キャプション・バッジの日英両言語 / 移動矢印の参照整合 /
**○✕ がハノイのルール(配置・移動)と一致**(絵と本文の食い違い防止)/ クリア図が左右反転 /
mirror_towers の往復。計 697 件パス

### 仕様書 §3.3

図版の存在・移植元・箱の実物色・キャプション方針を追記(P6 方針「実装に合わせて仕様書を直す」)

### 検証(ヘッドレス Chrome + CDP。手順はメモリ `pyxel-browser-verification` / P6 handoff)

- 日英 5 ページ×2 周をスクリーンショットで確認(ページ送り・とじる・言語切替も同時に確認)
- 調整 2 回: ○✕/バッジがコマ上端に浮いて見えたため塔側へ寄せた(VERDICT_CY/BADGE_CY 12→24)、
  小箱を水色→白(上記)

## 要判断(選んだデフォルト)

1. **コマ下キャプションは要所のみ**(あらまし・クリアの 2 ページ)。10px 和文フォントでは
   frontend の全キャプションが 320×240 に収まらないため、○✕ の理由は本文 3 行に委ねた
2. **図版データは frontend と二重管理**(TS→Python の手移植)。契約化はしない(画面表現であり
   モジュール間契約ではない)。frontend 側の図版を変えたら手で追随する
3. handoff の連番は P6a に続けて **P6b** とした(finish の様式は S{n} だが Pyxel 系は P 系列を継続)

## 契約からの逸脱

- なし(契約・既存コード・ランタイムとも変更なし)

## 既知の問題

- クリアページの ○ はコマ右上固定のため、右パネルの塔からやや離れて見える(frontend と同じ配置。
  320×240 では許容と判断)
- 実機ブラウザ(Safari / Edge / iPhone)での見た目確認は P6 から継続して未実施

## 次セッションへの注意

- ルール文言・図版を変えるときは `i18n.RULE_PAGES`(文言)と `rule_figures.RULE_FIGURES`(図版)の
  ページ数を揃える(テストが検知する)。frontend の図版変更時も同様に追随する
