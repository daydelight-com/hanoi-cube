# S16 引き継ぎ: 箱の完全姿勢復元(ひっくり返し・底面表示対応)

ユーザー報告「実箱で検証すると底面が表示されない。リアルな箱の様子を表示する
コンセプトと外れている」への対応。従来CVはヨーを mod 90° でしか推定せず表示は常に
面1が上だった(S8 要判断1)。今回、タグID→面番号(tag_master)と貼付規約から
箱の完全な姿勢(どの面が上か + ヨー全域)を復元し、3D表示が実箱のひっくり返し・
横倒し・回転と連動するようにした。

## 完了したこと

- **server/app/cv/geometry.py**:
  - 面規約定数を追加(正: `frontend/src/three/faces.ts` の対応。面1=+z上, 面2=-y手前,
    面3=+x右, 面4=+y奥, 面5=-x左, 面6=-z底): `FACE_NORMAL_LOCAL` /
    `TAG_IN_BOX`(各面のタグ座標系→箱ローカルの回転。貼付規約の数式化)/
    `UP_FACE_BASE`(「面Nが上」の基準姿勢)/ `_FACE_BY_AXIS`
  - `box_estimate()` が `face`(タグの面番号)を受け取り
    `(底面中心, up_face, yaw)` を返すように変更。完全姿勢 = `Rz(yaw) @ UP_FACE_BASE[up_face]`
  - **IPPE 2解曖昧性の解決**: `tag_pose_candidates()` で solvePnPGeneric の全解を取り、
    物理制約で選別する。旧実装は第1解の法線をスナップして位置だけ救っていたが、
    面ベースの姿勢復元では解の取り違えが up_face の誤りに直結するため選別が必須。
    選別基準は3つ(`box_estimate` のコメント参照):
    1. 可視タグの法線はカメラ側(裏向き解は +2.0 ペナルティ)
    2. **底面はマット下に潜れない**(`_BURIED_Z_MM=15`。鏡映解が側面タグを上面と
       誤認すると底面が -19〜-40mm に沈む)
    3. 法線は鉛直か水平(`_normal_snap_angle`。回転行列全体の軸平行性で測ると
       「別の軸がたまたま鉛直に近い」鏡映解を見逃すため法線だけで測る)
    第1解(再投影誤差最良)を既定とし、代替解はスコア改善が
    `_SOLUTION_SWITCH_MARGIN=0.25` を超える場合のみ採用(手回し中の軽い傾きnoise
    で鏡映解へ飛ぶと箱が沈むため。下記「実箱検証での回帰」)
- **server/app/cv/pipeline.py**: `_resolve_boxes()` が箱ごとに up_face を多数決
  (同数なら面番号最小)、ヨーは up_face が一致するタグの円環平均(単位ベクトル平均)
- **server/app/cv/tracker.py**: `BoxSighting.yaw90_rad` → `up_face` + `yaw_rad`。
  quat は `Rz(yaw) ⊗ q_base(up_face)` のハミルトン積で合成(`_pose_quat`)。
  ヨーの unwrap は mod 90° → ±π 境界の 2π 同値類展開に変更
- **server/tests/cv_scene.py**: 合成レンダラの面配置が faces.ts の規約と食い違っていた
  (旧: 面1〜4=側面, 面5=上面)のを `TAG_IN_BOX` / `UP_FACE_BASE` を直接使う実装に統一。
  `BoxPose.up_face` でひっくり返し・横倒しをレンダリングできるようにした
- **frontend/src/three/BoardScene.ts**: `setBoxes()` の底面中心→箱中心補正が
  箱ローカル上方向(`applyQuaternion`)だったのをワールド上方向に修正。
  旧quat(ヨーのみ)では無害だったが、反転quatでは箱が地面へめり込むバグだった。
  quat補間は既存の slerp がそのまま反転もなめらかに扱う。表示視点(HANOI_CAMERA_SIDE)
  とも独立(視点はどちらでも物理的に正しい面が見える)
- **ドキュメント**: `scripts/generate_tag_sheet.py` の貼り付けガイドと
  `docs/operations.md` に**貼付規約**を明記(下記 要判断2)。
  タグシートの旧ガイドは「向きは推奨・配置は自由」だった
- **テスト**(同一セッション): geometry +1(パラメトライズ5ケース: 正立/ひっくり返し/
  横倒し×2/155°回転で、実検出器を通して up_face とヨーの復元を検証)、
  pipeline: ヨーテストを全域化+ひっくり返しの quat 検証を追加、
  tracker: unwrap テストを ±π 境界に置換+quat 合成(面6+90°)の検証を追加
- `make check` 通過(server 200 / frontend 105 / cloud 7)

## 契約の変更

- **なし**。cv-interface.md の `quat` は元々「[x,y,z,w]、単位=無回転(面1が上)」で
  フル回転を表現できる形式のため、契約はそのまま。ws-messages / TS写しも型変更なし。

## 要判断として選んだデフォルト(CLAUDE.md 規則3)

1. **S8 要判断1(「タグ→物理面の貼付対応が原理的に不定」)を上書き**: tag_master は
   面番号を持ち、S8自身が「正立貼り」を運用ルール化しており、貼付規約を守れば対応は
   確定する。仕様§2.3「タグ1枚で『どの箱が・どの面を・どの向きで』が一意に決まる」と
   前提2「ひっくり返しへの追従」に沿う面ベース復元を採用した。
2. **貼付規約を新規定義**(タグシートガイド・operations.md に記載): 面1を上・面2を
   手前に置き、側面(2=手前,3=右,4=奥,5=左)は図柄正立、面1は図柄上端を奥へ、
   面6は「手前へ2回倒して」上端を奥へ。どの物理面を面1にするかは従来どおり自由。
3. **規約違反の箱の扱い**: 位置・盤面判定(スコア)には影響せず、3D表示の面が
   食い違うだけ。複数タグで up_face が食い違った場合は多数決で通す
   (警告ログは未実装。持ち上げ・傾き中は正常でも食い違うためノイズになりやすい)。

## 実箱検証での回帰と修正(同一セッション内)

- ユーザー実機検証で「箱を回転させると地面に埋まって表示される」を確認。原因は
  IPPE 2解選別の初版(回転行列全体の軸平行性のみで判定)が、手回し中の軽い傾き
  (約12°)で鏡映解(法線がちょうど鉛直に見える)を選び、側面タグを上面と誤認して
  底面を約 -edge/2 に沈めていたため。
- 再投影誤差による選別は実ノイズ下で信頼できないことを実測で確認
  (正解の2.6倍の誤差でも誤り側が第1解になるケースあり)。最終的に上記の
  3基準(裏向き・埋まり・法線スナップ)+乗り換えマージンに落ち着いた。
- 回帰テスト `test_tilted_box_not_buried`(±20°傾き×全ヨー×3位置の解析的スイープ、
  検出器なしの純幾何)を追加。
- 静置全ヨースイープ(5°刻み×正立/横倒し/ひっくり返し×3位置、実検出器)の
  単一タグ誤り率は 24/1501(1.6%)。ほぼ真横すれすれの入射角のタグ単独で、
  複数タグの多数決とトラッカー平滑化で吸収される水準(未対応のまま許容)。
- 修正後も「変わらない」との報告があり切り分けた結果、**ディスプレイのブラウザタブが
  修正前のフロントコード(applyQuaternion 版)を保持したまま**だったのが残因。
  ページ再読み込みで解消し、実箱の回転で埋まらないことをユーザーが確認済み。
  教訓: サーバー(uvicorn --reload)は自動反映されるが、開き続けている表示タブは
  Vite の自動リロードから取り残されることがある。表示系の修正後は必ずタブを再読込。

## 既知の問題・次セッションへの注意

- **実機検証が必要(最重要)**: 実箱のタグが貼付規約どおりに貼られているかは
  コードからは分からない。実CVで起動して箱をゆっくり回し・ひっくり返し、画面の箱が
  実物と同じ面・同じ向きで連動することを確認する(operations.md の検証手順)。
  食い違う箱はタグの貼り直しが必要になる可能性が高い(旧ガイドは配置自由だったため)。
- モックCV(mock.py)は常に正立(quat単位)を送る。ひっくり返しの表示を実CVなしで
  確認したい場合はモックCLIへの姿勢指定の追加が必要(未実装)。
- 面テクスチャ(three/textures.ts)は仮デザインのまま。底面(面6)が見えるように
  なったので、本番デザイン入稿時は6面すべての絵柄を確認すること。
- 持ち上げて傾けている最中の姿勢は「最近傍の軸平行姿勢」への近似(従来と同等)。
  中間角では up_face がフレーム間で切り替わり、slerp で回って見える(仕様上許容)。
