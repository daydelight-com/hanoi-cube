## 要判断(選んだデフォルトと理由)

1. **idle_ranking の表示時間**: 「1位表示+3s」はクライアント演出依存 → サーバーは
   `clamp(件数×1s, 2s..27s) + 3s` の暫定値(machine.py 冒頭の定数)。**S4 の演出実装と同期が必要**
2. **カウントダウン**: 仕様§5.6「GOと同時に計測開始」に従い、GO 送信(entry+3s)と同時に game_play へ
   遷移。`game_countdown` の ctx value="go" は snapshot 上ほぼ現れない
3. **mode_select のフォーカス**: 端でループしない(クランプ)。screens.md 行5の「ループ有無はS4で調整」
4. **practice の矢印初回押下**: left→「戻る」、right→「?」をフォーカス(仕様は初期位置未規定)
5. **rule_dialog の page_count**: 5 固定(契約 ctx 例の値。S4 でページ数確定時に定数を変更)
6. **記録URL基底**: env `HANOI_RECORD_URL_BASE`(既定 `https://hanoi-cube.example.com/records/`)。
   S9 で確定
7. **result 行23/24 の enter に input_mode ガードなし**(遷移表通り)。name モード中でも focus=decide で
   名前が有効なら確定される(物理的には keyboard 表示中に enter は来ない)
8. **永続化**: S2 は `MemoryStore`(プロセス再起動で消える)。SQLite(仕様§7.1)+Firestore は S9 で
   `PlayStore` 準拠実装に差し替え。アップロードキュー投入も S9(保存箇所に TODO コメントあり)

## 既知の問題・次セッションへの注意

- **未検証・要人間確認**: 実ブラウザ/iPad 実機での WS 再接続・30fps 描画は S3〜S5 で確認
  (S2 は TestClient での検証のみ)
- S10 運用課題: `HANOI_MOCK_API=0` の設定、WS の Origin 検証(または共有トークン)の要否判断
- game_play 中の `screen` メッセージの ctx.remaining_ms は最後の 1s tick の値(最大1秒古い)。
  正確な残時間は `timer` メッセージが正
- S4/S5(フロント)へ: 接続直後の最初の受信は必ず `snapshot`。ctx 変化(フォーカス移動等)は同一
  screen の `screen` メッセージで再送される。`boxes` は全画面で常時流れる。効果音はサーバーから
  `sfx` を送っていない(クライアント自律発音。最終決定は S6 で ws-messages.md §4 に追記)
- サーバー起動: `make dev`(uvicorn は websockets 依存を追加済み)。モック操作:
  `curl -X POST localhost:8000/api/mock/board -H 'content-type: application/json' -d '{"board":"L/MS/L"}'`
