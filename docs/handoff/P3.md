# P3 引き継ぎ: 3D 盤面 + ドラッグ&ドロップ

計画書 `docs/pyxel_app_development_plan.md` §4 の P3。`pyxel_app/` に Pyxel 依存層(盤面シーン・効果音)と
Pyxel 非依存層(ポインタ結線・指数平滑化)を追加し、ブラウザで 9 箱を塔・待機エリア間でドラッグ&ドロップできるようにした。
既存コード(`server/` `frontend/` `cloud/` `docs/contracts/`)とランタイム(`pyxel_app/runtime/`)は変更していない。

## 完了したこと

### `pyxel_app/scene/board_scene.py`(仕様書 §6.3。Pyxel 依存)

- Node ツリー `BoardScene` → `MatNode`(マット = 薄い box、塔マーカー 90mm 角 + A/B/C ラベル、スロット枠 `boxb`)、
  `BoxNode` x9(`box` + `boxb` 輪郭、`Collider(size=一辺, trigger=True, mass=0)`、タグ `"box"`)、`HighlightNode`(候補の二重枠。緑 11 / 赤 8)
- カメラ `look_at((0, 3.3, 1.5), (0, 0.2, -0.1))`、fov 60。320x240 でマット四隅と 3 段積みの上面が画面内に入る(テストで検証)
- `pick_box(sx, sy)`: `picking.screen_to_ray` → `self.raycast(..., hit_triggers=True, tags=["box"])` → 最初に当たった `BoxNode.box_id`
  (見えている箱がそのまま当たる。掴めるかの判定は `DragController.press` 側)
- `floor_point(sx, sy)`: レイとマット平面 y=0 の交点。`project(point)`: 逆変換(デバッグ用)
- `sync(dt)`: 各箱の目標位置を所在から求め `SmoothedPosition` で 1 ステップ進める。ドラッグ中の箱だけは追従点に即時(snap)。
  ハイライトは `PointerDriver.target / preview` から更新。最後に `Node.update()`
- cube の確認結果: `Collider.size` / `Primitive.box` / `Node.box` はいずれも**全長**(半径ではない)。`raycast` は最近傍から返す。
  `Node.update()` と `raycast` は `pyxel.init()` 無しで動く(→ 本物の Node ツリーで pytest できる)

### `pyxel_app/input/pointer.py`(§4.3〜§4.5。Pyxel 非依存)

- `PointerDriver(drag, query)`: `query` は `SceneQuery` Protocol(`pick_box` / `floor_point`)。`BoardScene` が実装し、テストは偽シーン
- `feed(sx, sy, held, inside)` を毎フレーム呼ぶ。押下エッジ → `press`(ピッキング → `DragController.press`)、押しっぱなし → `move`
  (床面追従点 → `layout.nearest_target` → `DragController.preview`)、解放エッジ → `release`(`DragController.release(target)`)。
  `inside=False` で解放 → `leave()` = `cancel()`(§4.5 ウィンドウ外)
- レイが床を外れたフレーム(画面上端)は直前の追従点を保持。押下時に床を外れていれば箱の足元を追従点にする
- `lifted_position`: `layout.lifted_center`(床上の点 + 1 箱分)

### `pyxel_app/scene/smoothing.py`(§6.3。Pyxel 非依存)

- `smoothing.ts` の写し: `damp_factor(λ, dt) = 1 - exp(-λ dt)`、`POS_LAMBDA = 12`(テストで TS ソースと照合)
- `SmoothedPosition`: `target` へ毎フレーム収束、残差 1e-4 未満で吸着(`settled`)。`snap()` で即時

### `pyxel_app/sfx.py`(§6.5。暫定)

- `Sfx` IntEnum で 7 種の番号を予約(BUTTON=0 .. TIMEUP=6)。P3 では `PLACE`(上昇音)と `FAIL`(下降ブザー)だけ定義。
  未定義の音は `play()` が無視する。チャンネル 3 を使用

### `pyxel_app/main.py`

- `p2_status()` と 3 行目の表示を削除し、`BoardState.initial()` → `DragController` → `PointerDriver` → `BoardScene.bind()` に置き換え
- `update()`: `pyxel.mouse_x/y` と `btn(MOUSE_BUTTON_LEFT)`、ウィンドウ内判定を `feed()` に渡し、`DropOutcome` で配置音 / 失敗音。
  `dt` は `time.monotonic()` 差分(上限 0.1 秒)
- HUD: `core OK`、`<version> / <fps>`(`FpsMeter`: 直近 1 秒の draw 回数)、盤面文字列、最後のドロップ結果。**D キー**で
  デバッグ重ね描き(ピッキング計算の投影点を赤十字で描く。レンダラとのずれ確認用。P4 で消してよい)

### `pyxel_app/scene/layout.py` の変更(P2 要判断 #1 の決定)

- `staging_slot_position()` を **2 段**に変更: 手前段(y = 0.15H)に L 列 3 スロット(ピッチ 85mm、中央寄せ)、
  奥段(y = 0.40H)に M 列(ピッチ 58)+ S 列(ピッチ 38)、列間 10mm、全体を中央寄せ(`STAGING_SLOT_MM`)
- 背の高い L を手前にした理由: L を奥段に置くと、カメラからの視線が L の上面をかすめて**塔 B の足元が隠れ、塔のマーカーをクリックすると L が当たる**
  (テスト `test_tower_bases_not_occluded_by_staging_boxes` で検出)。手前段 L の背面 82mm / 奥段 M の前面 94mm / 奥段 M の背面 144mm /
  塔上 L の前面 170mm で重ならない(`test_staging_boxes_do_not_overlap_each_other_or_towers`)
- `STAGING_Y_MM / STAGING_X0_MM / STAGING_PITCH_MM` は layout.ts との数値一致テストのため残したが、Pyxel 版の配置には使わない
- 他の関数(`nearest_target` など)は無変更。`test_layout.py` の 42mm ピッチ前提の期待値を更新

## 要判断(選んだデフォルト)

1. **待機スロット 2 段**(上記)。一列 42mm は不可能(9 箱で 465mm > 420mm)なので 2 段にした。L を手前にする理由も上記。
   mock CV の座標とは一致しなくなったが、Pyxel 版の待機エリアは仮想なので影響なし
2. **ドラッグ中の箱は平滑化せず追従点に即時**(λ=12 だと 0.2 秒遅れて指に付いてこない)。置いた瞬間から平滑化で「スッと収まる」
3. **見えている箱がそのまま当たる**(掴めない箱が手前にあっても奥の掴める箱を透過しない)。物理の挙動と同じ
4. `depth_offset(-1.0)` は使わない: 例と同じ値をマーカーに使ったら、マーカーが上に載った箱を透過して描かれた。マーカーは y を 2cm(0.02)浮かせるだけにした
5. 待機エリアの段間(y 差 74mm)はしきい値 47.5mm の外なので、段の中間で離すと「範囲外」で戻る。待機へ戻す操作は箱の上で離せばよいので許容
6. **塔マーカーは円柱ではなく 90mm 角の正方形**(仕様書 §4.1 は「円柱マーカー」)。cube の `circ` は向きの扱いが未確認で、
   ソフトウェアレンダリングの負荷も考え平面の正方形にした。見た目の調整は P5/P6 で(円にしたければ `MatNode.on_draw` だけ)
7. **待機スロットのハイライトは「実際に箱が収まるスロット」を指す**(`PointerDriver._resolve_staging`: 指したスロットが埋まっている・
   他サイズ列なら、元スロット → 自サイズ列の若い空き)。`place_in_staging` と同じ規則なので、ハイライトとドロップ結果が一致する
8. `test_layout.py` の layout.ts 数値一致テストは `STAGING_Y/X0/PITCH_MM` も照合し続ける(Pyxel 版の配置には未使用だが、
   mock CV との対応を将来取り直すときの基準として残す)

## 既知の問題

- CDP で連続操作した際に **1 回だけドラッグが無反応**になった(M1 を押して塔 A で離したが outcome なし。同じ操作の再実行は成功)。
  同時刻に実機マウスの `mousemove` がページに入っていたので干渉と推定しているが、Pyxel web の入力取りこぼしの可能性も残る。
  P4 以降で再現したら `feed()` の押下エッジ周り(`pyxel.btnp` との併用)を疑う
- ポート 8081 は引き続き前セッションの `python -m http.server`(PID 43075、`site/` 配信)が掴んでいる。本セッションもそれを使った
- HUD の表示位置・文言は暫定(P4 で SCORE / TIME / MISS に置き換える)
