# S18 引き継ぎ: 待機ランキングの並び順修正とせり上がり演出の作り直し

ユーザー報告「ランキングの順位が上の人が下に表示されている」への対応。原因は
待機画面(`idle_ranking`)が「下位から順にせり上がる」演出(仕様§5.2の旧記述)を
実現するために**表そのものを rank 降順に並べ替えて**流していたこと。停止時の画面は
1位が最下段になっていた。並び順を「1位が最上段」に固定したうえで、せり上がりの
向きと終点を作り直した。

## 完了したこと

- **frontend/src/display/screens/idleRankingRows.ts**(新規): 表示順を返す純関数
  `idleRankingRows()`。常に rank 昇順(1位が先頭)、同順位はサーバーの並びを保つ、
  入力配列は破壊しない。テストは `idleRankingRows.test.ts`。
- **frontend/src/display/screens/IdleRankingScreen.tsx**: 逆順ソートを廃止。
  演出は「表全体を表示領域の下端から上へせり上げる」に変更し、終点を高さで分岐:
  - 1画面に収まる → 終点0(見出し直下)で静止。1位が最上段のまま全件が見える
  - 収まらない → 最下位まで流し切ったあと `setTimeout(duration)` で先頭へ戻して静止。
    サーバーはこの静止の `IDLE_RANKING_TAIL_MS`(3秒)後にタイトルへ戻るので、
    **最後に映るのは必ず1位**になる
    計測は `area.clientHeight` / `el.offsetHeight`(旧実装の vh 固定値から変更)。
- **frontend/src/display/screens/idleRankingTiming.ts**: 終点を求める純関数
  `idleRankingEndY()` を追加。`SCROLL_MAX_MS` を 27秒 → **120秒**に延長。
- **server/app/state/machine.py**: `IDLE_RANKING_SCROLL_MAX_MS` を同値(120秒)に。
  サーバーのタイムアウトとクライアント演出の終了を一致させる不変条件は維持。
- **frontend/src/display/ui/retro.css**: 未使用だった `.retro-ranking-rise` /
  `@keyframes retro-rise` を削除し、せり上がり領域 `.retro-ranking-rise-area`
  (flex:1 / overflow:hidden)を追加。
- **テスト**: 表示順3件(順序・同順位の安定性・非破壊)、終点算出2件、
  表示時間のクランプ(サーバー側。10件=13秒 / 200件=123秒)を追加。`make check` 全通過。
- **実機確認**: dev サーバーの表示画面で、2件の実データで1位が最上段に静止すること、
  100件を注入した一時パッチで等倍のまま流れて最後に1位が最上段で静止することを確認。

## 契約・仕様からの逸脱(今回変更した箇所)

1. **docs/contracts/screens.md 行11 を変更**: 「全件を下位からせり上がり表示」→
   「全件を1位が最上段の並びでせり上がり表示(最後に1位で静止)」。
   影響を受ける実装は `IdleRankingScreen.tsx` のみで、同一セッションで修正済み。
   状態機械・WSメッセージ・ctx 型には変更なし。
2. **docs/specification.md §5.2 を変更**: 「全件を下位から順に」「約20〜30秒で
   流し切るペースに速度を自動調整」→「1位を最上段」「1行1秒を保ち最長120秒」。
   旧記述は件数が増えると自動的に速くなる設計で、100件なら1行0.27秒(約4行/秒)に
   なり自分の名前を探せない。**ユーザー判断で可読性を優先**し、縮小や早送りをせず
   時間を延ばす方針に変更した。

## 要判断(次セッションへ)

- **上限120秒は暫定**。待機ループ1周が「タイトル5秒 + ランキング最大123秒」になる。
  ブースの回転を見て長すぎるなら60秒(100件で1行0.6秒)への短縮を検討する。
  変更するときは `machine.py` と `idleRankingTiming.ts` の**両方**を同値にすること
  (テストが両側の値を検証している)。
- **ws-messages.md §の `rank_tick` / `fanfare`** は「idle_ranking のせり上がり演出」
  用として契約に残っているが、仕様§5.12(行340)の「待機ランキングのせり上がりは
  無音とする」に従い `IdleRankingScreen` は現在どちらも鳴らしていない(S18以前からの
  乖離。今回の変更とは無関係)。SEを復活させるなら契約と仕様のどちらが正かの確定が先。

## 既知の問題・次セッションへの注意

- **idle_ranking 表示中にディスプレイが再接続・リロードすると演出が最後まで届かない**
  (Codexレビュー指摘。検証済み・今回は見送り)。`/ws/display` の snapshot は
  経過時間を含まず(`server/app/api/ws.py`)、ctx も entries だけ(`_ctx()`)なので、
  クライアントは全 duration を最初からやり直す。一方サーバーのタイマーは
  `_entered_ms` 基準で進み続けるため(`machine.py` の `tick`)、最悪ケースでは
  1位の静止に到達する前に idle_title へ切り替わる。**上限を120秒に延ばしたことで
  ずれ幅は最大120秒に拡大している**。根治には ctx に経過時間(または開始時刻)を
  足す必要があり `docs/contracts/screens.md §5` の契約変更になるため見送った。
  待機ループの次の周回で正常化する・ブース運用でディスプレイのリロードは稀、
  という判断。契約を触るセッションが来たら合わせて直すとよい。

- 終点の計算がピクセル計測になったため、**表示中にウィンドウサイズが変わると
  終点がずれる**(ResizeObserver は入れていない)。待機ループで画面が入り直すたびに
  再計算されるため自己回復する。固定解像度のブース運用では問題にならない想定。
- 1画面に収まらない場合の「先頭へ戻す」はトランジションなしの瞬間移動(意図的)。
  スクロールで戻すと下位→上位の逆再生に見えるため。
