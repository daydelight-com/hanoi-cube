# S25 引き継ぎ: 本番1日目朝の高さ精度調整(カメラ45°化+表示側の接地自動補正)

本番1日目(2026-08-21)開場前の調整記録。症状は「位置は正確だが高さがおかしい
(接地箱が沈む/重ねると沈む/移動中に沈んで浮く)」。物理調整+表示側の小さな
コード追加で解消し、開場前にユーザーが実プレイで正常動作を確認済み。

## 完了したこと

### 原因の特定(実測ベース)

`/ws/display` を直接購読して箱の生座標を条件別に計測した結果:

- **タグ1面だけで推定した瞬間の高さ誤差が±30〜50mm**で、面と位置によって符号も変わる
  (例: 同じ場所で単面[0]は+26、単面[4]は-31)。タグ印刷サイズずれ説は符号が揃わない
  ことから棄却。斜めから見た小さなタグ(約36px)の単面姿勢推定の原理的な弱さ。
- 2面以上見えていれば常に数mm〜+14mmに収まる(大・中・小とも)。
- 従来のカメラは**見下ろし角約57°と急**で、箱の側面タグが寝て検出が落ち、
  上面単独になった瞬間に高さが跳んでいた。「昨日は起きなかった」のは
  前日の検証が塔Bの1点だけで、A/C・移動・積みを踏んでいなかったため(潜在特性)。
- 朝一にはこれと別に、前日夕の保存キャリブレーションと当朝の条件のずれによる
  一様沈み(-22〜-31mm)もあった(S24の顛末と同型。リセットで解消)。

### 物理調整: カメラを見下ろし約45°へ

カメラを下げて(高さ565→388mm、水平位置ほぼ不変)見下ろし角を57°→47°にした。
効果: 側面タグの検出が安定して常時2面推定になり、単面時ですら誤差±17mm以内に改善。
実測: 塔A 280フレーム連続正常、大箱+中箱の積みギャップ1.3mm、3塔フル積みで
全箱・全フレーム正しい area/level 判定。

副作用として接地箱の底面zが一様に約-12.5mmへオフセット(キャリブレーション解の
面推定バイアス。57°では+13だった=角度に対して系統的で、ゼロ交差は約52°と推定)。
判定には無害(許容25mm)だが3D表示で箱が埋まって見えるため、次の表示側補正を追加。

### コード変更: 表示専用の接地自動補正

- `frontend/src/three/groundOffset.ts`(新規): 「可視かつ level=0 と判定済みの箱の
  底面は物理的に z=0」という事実から、底面z平均のずれを推定し補正量を返す純関数。
  目標値を±25mm(`GROUND_OFFSET_MAX_MM`)でクランプ、ゲイン0.08で指数追従
  (30fps入力で約1秒収束)。
- `frontend/src/three/BoardScene.ts`: `setBoxes()` で補正量を更新し、**可視箱の描画
  高さにのみ**加算(非可視の保持・プレースホルダ位置には掛けない)。
- `frontend/src/three/groundOffset.test.ts`(新規): 境界6件(空・非可視・level=null/1・
  符号両方向・収束・クランプ)。frontend check 全128件通過。
- サーバー側の判定(area/level/積み許容)には一切影響しない。定数決め打ちでないため
  再キャリブレーションでずれの量・符号が変わっても自動追従する。

## 契約からの逸脱・追加判断

- なし。契約に「表示は pos_mm をそのまま描く」といった規定はなく、表示側の
  補正は契約の範囲内(ws-messages.md は視点反転のみ規定)。

## 既知の問題

- **単面推定の高さ誤差(±17mm@45°)は残存**。判定許容25mm内だが、カメラ角度を
  再び急(50°超)にすると±30mm超へ悪化し判定抜けが再発する。**カメラは見下ろし
  約45°を維持すること**(現設置: 高さ約39cm・マット後方約36cm)。
- 接地バイアス(現-12.5mm)はキャリブレーション解に依存して変わる。表示は自動補正
  されるが、判定側は生値のまま。バイアスが±25mmへ近づくと判定が壊れ始めるので、
  設営変更時は必ず「大箱を塔に置いて area が付くか」を確認する。
- キャリブレーション保存は1ワーカープロセス初回のみ・復元起動では焦点距離ログが
  INFOに出ない等の運用注意は S24 参照。
