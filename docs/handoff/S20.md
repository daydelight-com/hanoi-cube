# S20 引き継ぎ: H/A/N/O/I カスタムマーカーPoC(hanoi_markers/)

ユーザー依頼による独立タスク。人間には H/A/N/O/I の文字として読め、OpenCVには
5種類のIDとして安定認識できる7×7カスタムマーカーを `cv2.aruco` のカスタム
Dictionaryとして設計・実装した。**本番CV(server/app/cv/、tag36h11)と契約
(docs/contracts/)には一切手を入れていない**。自己完結PoCとして `hanoi_markers/`
に隔離してある。

## 完了したこと

### 1. マーカー設計と探索(`hanoi_markers/src/`)

- ビット規約 **1=白 / 0=黒**(OpenCV arucoの内部規約と同一。
  `generateImageMarker` の実験で確認してから採用)。ID対応 0=H, 1=A, 2=N, 3=O, 4=I。
- 各文字を「固定bit(文字ストローク。最適化後も欠けないことをテストで保証)」と
  「変更可能bit(ストロークに上下左右隣接する背景セルのみ、1文字最大6bit)」に分離。
  I はフルバーだと I(90°) が H(0°) と完全一致するため、ベース形から上下バーを短縮。
- ランダム再スタート付き simulated annealing(seed=42、6再スタート×20,000反復、
  約13秒)で 5文字×4回転=20パターン間の最小Hamming距離を最大化。
  結果: **最小距離10**(最小ペアはOの回転同士)、文字間の最小12、変更bit合計26
  (H6/A2/N6/O6/I6、すべて白の追加)。結果は `src/optimized_patterns.json` に
  コミット(seedで完全再現可)。
- `maxCorrectionBits=3` を採用(理論上界 floor((10-1)/2)=4 の安全側。
  `src/dictionary.py` の `MAX_CORRECTION_BITS_CAP`)。

### 2. 実装物

- `src/marker_patterns.py` ベース形・変更可能マスク・JSON入出力・ASCII表示
- `src/optimizer.py` SA探索・Hamming距離・20×20距離行列・評価
- `src/dictionary.py` `create_hanoi_dictionary()`(`getByteListFromBits` →
  `cv2.aruco.Dictionary`)
- `src/generator.py` PNG生成(黒枠+quiet zone、cell_size等指定可)
- `src/detector.py` `ArucoDetector` 検出・枠+ラベル描画
- `scripts/optimize_markers.py` / `generate_markers.py` / `detect.py`
- `markers/H.png` 〜 `I.png`(生成済みコミット)
- `README.md`(採用パターンのASCII、original/optimized/diff、距離・訂正bitの根拠)

### 3. 検証(すべて実施済み)

- pytest 69件全パス: PNG再認識(ID一意)、4回転すべて同一ID(20件)、
  劣化耐性(縮小0.15倍・Gaussian blur・射影変換・ガウスノイズ、20件)、
  偽陽性(無地・乱数・市松の未知マーカー不検出)、誤り訂正の実測
  (1bit=既定で訂正 / 2bit=既定で棄却 / 3bit=rate1.0で訂正)、
  設計制約(最小距離≥8、ストローク完全保存、変更bitマスク内・6bit以下、LABELS)、
  成果物一致(JSON stats=実評価、設計値固定、PNG=再生成と一致)
- 5マーカー混在合成シーンでの `detect.py` エンドツーエンド(5文字全検出)
- 実行は server venv を利用: `cd server && uv run pytest ../hanoi_markers/tests -q`
  (OpenCV 5.0.0 は server の依存に既存。単体利用向け requirements.txt も同梱)

### 4. レビュー(super-review)

- local-code-review: Low 3件(未使用import GRID / maxCorrectionBitsロジックの重複 /
  generator の入力値検証なし)→ 3件とも修正済み。
- security-review: 指摘ゼロ(ネットワーク・サブプロセス・デシリアライズなしの
  ローカルPoC)。
- Codexレビュー: 9件(Med 3 / Low 6)→ 全件正当と検証し修正済み。主なもの:
  - **実効誤り訂正は1bit**: `maxCorrectionBits=3` でも OpenCV 既定の
    `errorCorrectionRate=0.6` により受理閾値は floor(0.6×3)=1bit。既定は誤検出
    最小の 0.6 のまま維持し、README に実効値と rate=1.0 での3bit訂正を明記、
    1/2/3bit誤りの実測テストを追加。
  - 訂正bit数の算出が JSON の記録値(stats)依存だった → 読み込んだパターン
    本体から毎回計算するよう変更(パターンとstatsの乖離時に過大訂正しない)。
  - テストが設計値を固定していなかった → stats=実評価の一致・設計値
    (最小距離10、変更bit H6/A2/N6/O6/I6、訂正3)・PNG再生成一致を固定する
    テストを追加。ほか imwrite 失敗検知、JSONの0/1検証、SAパラメータ境界
    検証、README表現修正。
